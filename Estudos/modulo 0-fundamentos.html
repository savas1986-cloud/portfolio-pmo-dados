Conceitos-chave

Dado → Informação → Conhecimento
Dado: fato bruto sem contexto  ·  Informação: dado com contexto e estrutura  ·  Conhecimento: padrão acionável identificado na informação.
Dado: "23.547" Informação: "23.547 transações Pix — Sudeste — jun/2025" Conhecimento: "Clientes com 3+ Pix/mês têm 2,3× mais propensão a crédito nos 90 dias seguintes"
📌 PMO: quando a área pede "um relatório", pergunte o que você vai fazer com esse dado? A resposta revela se precisa de dado, informação ou conhecimento — três projetos com escopos completamente diferentes.
Tipos de Dados
Estruturado — tabelas SQL, schema fixo. Transações, cadastros, saldos.

Semi-estruturado — JSON, XML. APIs do Open Finance, respostas de serviços.

Não-estruturado — e-mails, gravações de call center, PDFs. Requer NLP, OCR ou ML para processar.
📌 No F1RST: 80% será estruturado. Dado não-estruturado = squad diferente e prazo diferente.
KPI · Métrica · Dimensão · Granularidade
Métrica — qualquer valor mensurável.
KPI — métrica estratégica vinculada a um objetivo de negócio. Todo KPI é métrica; nem toda métrica é KPI.
Dimensão — contexto para fatiar (squad, vertical, região, período).
Granularidade — nível de detalhe. Quanto mais fina, mais analítica — e mais difícil reverter depois.
Taxa de inadimplência 3,2% (métrica/KPI) → por segmento (dimensão): Premium 1,8% | Básico 6,4% → por dia (granularidade): spike nos dias 12 e 13 de maio
Real-time vs Batch
Real-time (streaming) — processado assim que o dado chega. Necessário em alertas de fraude e monitoramento ao vivo. Exige Kafka ou Event Hub — arquitetura complexa e cara.

Batch — dados acumulados e processados em bloco num horário agendado (ex: toda noite às 2h). Padrão para a maioria dos dashboards corporativos.
📌 Antes de aprovar "real-time": confirme se o solicitante precisa de atualização por minuto ou se batch diário resolve — são soluções com custos e complexidades completamente diferentes.
Modelagem Dimensional — Estrela
Tabela Fato — eventos mensuráveis. Cada linha = 1 fato (1 transação, 1 chamado, 1 deploy). Contém os valores numéricos e as chaves das dimensões.  ·  Tabela Dimensão — contexto: cliente, produto, tempo, canal, squad.  ·  Esquema Estrela — fato central rodeada pelas dimensões. Mais performático que o floco de neve. Para Power BI: sempre estrela.

Glossário

23 termos
Data Warehouse (DW)
Repositório de dados estruturados com schema definido antes da carga. Alta confiabilidade, custo elevado. Padrão para relatórios regulatórios e histórico financeiro.
Data Lake
Armazenamento de dados brutos em qualquer formato. Schema definido na leitura (schema on read). Escala massiva, custo baixo. Risco: virar "data swamp" sem governança.
Lakehouse
Combina Data Lake + Data Warehouse: armazena bruto mas adiciona transações ACID e SQL analítico completo. Databricks e Microsoft Fabric são exemplos. É o que o F1RST usa.
ETL
Extrair → Transformar (em staging intermediário) → Carregar no destino. Padrão legado e de compliance. Se falha, dado fica preso no staging; destino sem dado.
ELT
Extrair → Carregar bruto no destino → Transformar lá dentro. Padrão cloud moderno. Se falha, dado chegou mas transformação não rodou — recuperação mais rápida.
KPI
Key Performance Indicator. Métrica estratégica vinculada a um objetivo de negócio declarado. Todo KPI é métrica, mas nem toda métrica é KPI.
OKR
Objectives and Key Results. Framework com 1 objetivo qualitativo + 2–5 resultados-chave mensuráveis. Define onde chegar num ciclo (trimestral/semestral). Diferente do KPI, que mede performance contínua.
Métrica
Qualquer valor mensurável. "Número de squads" é uma métrica. "Cumprimento de SLA" é um KPI. A distinção está no vínculo com um objetivo estratégico declarado.
Dimensão
Contexto pelo qual uma métrica é analisada: por squad, por vertical, por região, por período. É a dimensão que transforma um número em insight.
Granularidade
Nível de detalhe dos dados. Granularidade fina (diária): mais analítica. Granularidade grossa (mensal): perde detalhe permanentemente. A escolha precisa entrar no escopo antes do dado ser persistido.
Tabela Fato
Tabela central no modelo dimensional. Cada linha = 1 evento mensurável (1 transação, 1 deploy, 1 chamado). Contém os valores numéricos e as chaves para as dimensões.
Modelagem Estrela
Esquema dimensional com 1 tabela fato central rodeada por tabelas dimensão. Mais performático que o floco de neve (snowflake). Para Power BI: sempre estrela.
BI (Business Intelligence)
Conjunto de processos, tecnologias e ferramentas que transformam dados brutos em informação útil para decisões de negócio. Power BI é uma ferramenta de BI — não o BI em si.
OLAP
Online Analytical Processing. Sistemas para analisar grandes volumes de dados históricos. Lê muito, agrega, consolida. O Data Warehouse é o ambiente OLAP por excelência.
OLTP
Online Transaction Processing. Sistemas que registram transações com alta velocidade e consistência. O sistema do Pix é OLTP. Escreve muito, lê pouco, linha por linha.
Drill-down
Navegar de um nível agregado para um nível mais detalhado no mesmo visual. Ex: Total Brasil → Sudeste → SP → Agência. Cada clique aprofunda o detalhe.
Drill-through
Navegar de um visual para uma página diferente do relatório mantendo o contexto do item selecionado. Clicou num produto → abre a página de detalhe daquele produto.
Slicer
Filtro visual interativo no Power BI. Controla todos os outros visuais da página. É um visual como qualquer outro, mas funciona como controlador geral do dashboard.
Dashboard
Painel com múltiplos visuais em uma tela para monitoramento rápido. Foco em identificar anomalias. Não é o lugar para análise profunda — é o lugar para perceber que algo saiu do normal.
Relatório
Documento analítico com mais profundidade que o dashboard. Várias páginas, tabelas e filtros. No Power BI, o arquivo .pbix é o relatório; o dashboard é uma composição de visuais fixados de um ou mais relatórios.
Scorecard
Painel de acompanhamento de metas com indicadores de status (✅ no prazo / ⚠️ atenção / ❌ atrasado). Responde "estamos no caminho certo?" para cada objetivo.
Real-time (Streaming)
Dados processados assim que chegam. Necessário para alertas de fraude e monitoramento ao vivo. Exige Kafka ou Event Hub — arquitetura complexa e cara. Confirme se é realmente necessário antes de aprovar.
Batch
Dados acumulados e processados em bloco num horário agendado (ex: toda noite às 2h). Padrão para a maioria dos dashboards corporativos. Mais simples, estável e econômico que real-time.

📋 Demanda: Dashboard de Monitoramento de Requisições — Time de Sustentação

KPIs: Cumprimento de SLA por requisição · Volume de requisições abertas e encerradas

Dimensões: Status · Analista · Área · Motivo · Categoria · Prioridade (Alta/Média/Baixa) · Período

⚠️ Gap crítico: Enquanto o pipeline ITSM não estiver disponível no Databricks, não há dado para desenvolver o painel. Data de início real depende da conclusão da ingestão em jun/2026.

📌 O "Gap crítico" é o que diferencia uma especificação de PMO de uma lista de requisitos — ele protege o prazo antes do projeto começar e estabelece expectativas realistas com o solicitante.

Insights da Aula

🏗️
O Databricks que o time chama de "Data Lake" é na verdade um Lakehouse
Databricks usa Delta Lake por baixo, que adiciona transações ACID e schema gerenciado ao armazenamento bruto. Isso permite SQL analítico e modelos de ML no mesmo lugar — característica de Lakehouse, não de Data Lake puro. Usar o termo correto em reuniões técnicas mostra domínio do assunto.
⚡
Falha no ELT ≠ falha no ETL — o estado do dado é diferente
Quando o ELT falha, o dado bruto já está no Databricks — só a transformação não rodou. No ETL, o dado fica preso no staging intermediário. A recuperação do ELT é mais rápida: é só re-executar a transformação, sem re-extrair da origem.
👥
Cliente solicitante ≠ usuário final — mapeie os dois sempre
A Área de Produtividade (CIO Office) pediu o painel e define os requisitos. Toda a F1RST consome. Uma mudança validada com o solicitante impacta todos os usuários. Escopo pequeno, risco alto — mapear ambos os stakeholders é parte do escopo do projeto.
🛡️
Gap crítico na especificação protege o prazo antes de começar
Mapear o que está bloqueando a execução (como um pipeline ainda não disponível) na própria especificação da demanda é uma prática de PMO que evita surpresas de prazo e estabelece expectativas realistas desde o início — antes de qualquer comprometimento de data.
🎯
Prioridade é dimensão, não métrica
Alta/Média/Baixa são atributos para fatiar dados, não valores a medir. A pergunta certa é "qual o cumprimento de SLA por prioridade?" — e não "qual é a prioridade?". Saber fazer essa distinção agiliza qualquer levantamento de requisitos com a área de negócio.
