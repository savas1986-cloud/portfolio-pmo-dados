Aula 1 — Interface e Conexão de Dados
📚

Os 3 Views do Power BI Desktop

📊 Report View — onde os visuais são criados
Canvas em branco onde gráficos, cartões e filtros são montados. É onde o usuário final vai interagir com o painel.
📌 É aqui que você vai passar 80% do tempo.
🗃 Data View — inspecionar os dados
Equivalente ao SELECT * FROM tabela LIMIT 10 do SQL. Mostra linhas, colunas e tipos de cada tabela carregada.
📌 Usar sempre para validar se os dados foram importados corretamente.
🔗 Model View — relacionamentos entre tabelas
Representa visualmente o que o SQL faz com JOIN: cada linha conectando tabelas é uma relação entre colunas. O 1 e o * indicam o lado único e o lado múltiplo da relação.
-- Equivalente visual de: JOIN Customers ON Orders.CustomerID = Customers.CustomerID -- No Model View vira uma linha conectando as duas tabelas -- com "1" do lado de Customers e "*" do lado de Orders
Aula 2 — Power Query
⚙

Limpeza e Transformação de Dados

💡
O que é o Power Query: é o "SQL de limpeza" do Power BI. Tudo que você faria com WHERE, ROUND e tratamento de NULL no SQL, o Power Query faz com interface visual antes dos dados chegarem aos visuais.
Erro real encontrado e resolvido — DataFormat.Error em colunas de data
🔴 DataFormat.Error: Não conseguimos analisar a entrada fornecida como um valor Date.
O que aconteceu: o Power BI gerou automaticamente um passo "Tipo Alterado" que tentou converter as datas usando o locale do sistema (português). O formato ISO do Northwind (2016-07-04) causou 17% de erros. Quando os passos "Tipo Alterado com Localidade" foram adicionados depois, eles receberam valores já corrompidos — e não conseguiram converter.
✓ Solução aplicada
Clicar no passo "Tipo Alterado" nas Etapas Aplicadas → editar a fórmula na barra de fórmulas → trocar type date por type text para as colunas OrderDate, RequiredDate e ShippedDate → refazer a conversão com localidade "Inglês (Estados Unidos)" diretamente nesse passo.
📌 Lição: a ordem dos passos no Power Query é obrigatória
Cada passo transforma o resultado do anterior. Um erro criado em um passo anterior não é corrigido por um passo posterior — é propagado. Quando um passo tem ✗ vermelho, o problema quase sempre está numa etapa anterior, não no passo marcado.
Etapas Aplicadas típicas: Fonte → Cabeçalhos Promovidos → Tipo Alterado → Linhas em Branco Removidas. A ordem é fixa — não dá para colocar WHERE antes de FROM.
Aula 3 — Modelagem de Dados (Star Schema)
⭐

Star Schema — O Padrão de Ouro para PMO

💡
Por que é chamado de Star Schema: a tabela fato fica no centro e as dimensões ao redor formam uma estrela. É o mesmo padrão que alimenta o Databricks da empresa.
Regra dos relacionamentos
Tabela fato (lado *): registra eventos — pedidos, demandas, vendas. Tem muitas linhas.

Tabela dimensão (lado 1): descreve quem ou o quê — squads, status, prioridade. Tem poucas linhas.
📌 Nunca conecte duas tabelas dimensão diretamente entre si. Toda relação passa pela tabela fato. Linha tracejada = relacionamento inativo = ambiguidade = problema.
Star Schema do Painel de Produtividade
squads (1) → demandas (*) status (1) → demandas (*) prioridade (1) → demandas (*) categoria (1) → demandas (*) responsaveis(1) → demandas (*)

Hierarquia de data — como resolver o agrupamento por mês
Quando uma coluna de data é adicionada ao eixo, o Power BI cria uma hierarquia automática (Ano > Trimestre > Mês > Dia). Para exibir 18 meses separados, é necessário expandir todos os níveis com o botão ↓↓ e remover Trimestre e Dia do eixo, mantendo Ano e Mês.
📌 Sem tabela calendário, a hierarquia agrega todos os "janeiros" em um único ponto. A solução completa vem no Módulo 5 com CALENDARAUTO().
Aula 5 — DAX Básico
⚡

4 Medidas DAX para Análise de SLA

💡
DAX vs SQL: uma medida DAX é como uma subquery que roda automaticamente no contexto de cada visual. Quando colocada num gráfico por squad, ela calcula o SLA de cada squad individualmente — sem nenhuma fórmula extra.

Medida 1 — SLA Cumprido %
SLA Cumprido % = DIVIDE( COUNTROWS( FILTER(demandas, NOT(ISBLANK(demandas[DataFechamento])) && demandas[DataFechamento] <= demandas[DataPrazo] ) ), COUNTROWS( FILTER(demandas, NOT(ISBLANK(demandas[DataFechamento])) ) ), 0 -- evita divisão por zero )
📌 DIVIDE é sempre preferido a "/" no DAX porque trata automaticamente a divisão por zero. FILTER aplica a condição linha a linha. ISBLANK detecta datas ausentes (demandas ainda abertas).
Medida 2 — Demandas no Prazo
Demandas no Prazo = COUNTROWS( FILTER(demandas, NOT(ISBLANK( demandas[DataFechamento])) && demandas[DataFechamento] <= demandas[DataPrazo] ) )
Medida 3 — Demandas em Atraso
Demandas em Atraso = COUNTROWS( FILTER(demandas, NOT(ISBLANK( demandas[DataFechamento])) && demandas[DataFechamento] > demandas[DataPrazo] ) )
Medida 4 — Tempo Médio de Resolução (dias)
Tempo Médio Resolução (dias) = AVERAGEX( FILTER(demandas, NOT(ISBLANK(demandas[DataFechamento])) ), DATEDIFF( demandas[DataAbertura], demandas[DataFechamento], DAY ) )
📌 AVERAGEX itera linha a linha sobre a tabela filtrada e calcula DATEDIFF para cada uma. É o equivalente ao AVERAGEX/DATEDIFF do SQL Módulo 1.
Aula 6 — Interatividade
🖫

Segmentadores, Drill-through e Matrix

Segmentador de Squad
Filtro dropdown que atualiza todos os visuais da página simultaneamente. Campo: squads[Squad]. Configurado como lista suspensa com opção "Todos".
📌 Um único clique filtra 5 visuais ao mesmo tempo. Isso é o que diferencia um dashboard de uma planilha.
Segmentador de Data (Entre)
Barra deslizante com data de início e fim. Campo: demandas[DataAbertura]. Configuração: Segmentador → Entre. Filtra todo o painel pelo período selecionado.
📌 Selecionar Jan-Out/2024 reduziu de 420 para 225 demandas em todos os visuais simultaneamente.
Drill-through — navegação interativa entre páginas
Clicar com botão direito numa barra do Squad Crédito → Drill-through → Detalhe Squad abre uma página filtrada automaticamente para aquele squad.
-- Configuração na página de destino: Formato → Informações da página Tipo de página: Detalhamento Drill through a partir de: squads[Squad] -- Para usar: botão direito na barra do squad -- → Drill-through → Detalhe Squad -- Botão ← volta para a página anterior automaticamente
📌 O campo "Tipo de página: Detalhamento" é o que ativa a funcionalidade. Sem isso, a opção não aparece no menu de contexto.
Matrix Visual — Squad × Status
Tabela dinâmica que cruza duas dimensões. Linhas: squads[Squad] · Colunas: status[StatusNome] · Valores: Contagem de demandas[DemandaID].

🔑

Insights do Módulo 2

🔗
Power BI Model View é o JOIN do SQL em forma visual
Cada linha no Model View representa exatamente o que um JOIN faria: conecta duas tabelas pela coluna em comum. O "1" e o "*" são os mesmos lados do relacionamento que você aprendeu com INNER JOIN e LEFT JOIN no Módulo 1.
🔴
A ordem dos passos no Power Query é tão obrigatória quanto no SQL
Um erro gerado num passo anterior é propagado para todos os passos seguintes. Quando um passo tem ✗ vermelho, o problema quase sempre está numa etapa anterior. Mesma lógica de depuração do SQL: rodar a query interna primeiro, validar o resultado, depois construir a externa.
🎨
Cores semânticas comunicam antes da legenda
Verde = concluído, vermelho = bloqueado/crítico, cinza = cancelado/baixa. Essa convenção é universal — qualquer gestor entende sem ler a legenda. Dashboards que precisam de explicação não são dashboards, são relatórios.
⚡
Uma medida DAX é contextual por natureza
A medida SLA Cumprido % calcula automaticamente o SLA de cada squad quando colocada num visual por squad, o SLA de cada prioridade num visual por prioridade, e o SLA geral num cartão — sem nenhuma fórmula extra. É o equivalente de uma subquery que se adapta ao contexto.
📊
Squad Pagamentos bloqueado é o alerta que o CIO precisa ver
8 demandas bloqueadas — maior absoluto entre os squads, num squad que processa os produtos de maior impacto financeiro. A matrix Squad × Status revelou isso em segundos. Esse é o valor de um painel de PMO: não contar o que aconteceu, mas mostrar onde a atenção é urgente.
🎯
SLA uniforme entre prioridades é um sinal de alerta
Crítica (75,86%) e Média (75,51%) com SLA práticamente idêntico indica que demandas críticas não estão sendo tratadas de forma diferenciada. Em um dashboard real, esse seria o primeiro questionamento levantado numa reunião com o CIO.
