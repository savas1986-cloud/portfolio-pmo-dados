Aula 1 — Governança de Dados
🏛

Conceitos, Papéis e Estrutura

💡
Governança de Dados em uma frase: conjunto de regras, processos e responsabilidades que definem quem pode acessar, modificar e usar os dados. No banco, você já vive isso: aprovações de acesso, políticas de retenção, classificação de informações.
Os 4 papéis essenciais
PapelResponsabilidadeQuem geralmente é
Data OwnerDefine regras de uso, aprova acessos, responsável pelo dadoGestor de negócio (Head, Diretor)
Data StewardGarante qualidade, documenta, monitora o dado no dia a diaAnalista sênior, PMO de Dados
Data CustodianArmazena e protege tecnicamente o dadoTime de Engenharia / TI
DPOData Protection Officer — conformidade com LGPDÁrea jurídica / compliance
📌 Data Steward é o papel de PMO de Dados. É quem conecta o negócio à tecnologia na gestão do dado — valida qualidade, documenta e garante que o KPI publicado reflete a realidade.
Data Catalog
Inventário de todos os dados da organização. Responde: quais dados existem, onde estão, quem é o dono e o que significam.
📌 Ferramentas: Microsoft Purview, Alation, DataHub. No Databricks da empresa, o catálogo é o ponto de referência antes de qualquer nova demanda de dados.
Data Lineage
Rastreabilidade do dado. Responde: de onde veio esse número? Permite saber que o KPI do dashboard veio de tal tabela, que veio de tal sistema fonte.
Jira (demandas) → ELT → Databricks Gold → Power BI → KPI
📌 Quando um número é questionado numa reunião, Data Lineage é a prova de origem.
As 6 dimensões de qualidade de dados — FACT+UV
DimensãoPergunta que respondeExemplo de problema
CompletudeO dado está preenchido?DataFechamento em branco para demanda concluída
AcuráciaO dado está correto?Nome do squad errado por erro de digitação
ConsistênciaO mesmo dado tem o mesmo valor em sistemas diferentes?SLA 30 dias no Jira, 20 dias no ServiceNow

Aula 2 — LGPD na Prática em Banco Regulado
🛡

Bases Legais, Tipos de Dados e Privacy by Design

💡
LGPD em banco regulado: em instituições financeiras, LGPD é parte do design de qualquer iniciativa de dados — não um item de compliance adicionado no final. Um PMO de Dados precisa identificar dado pessoal, dado sensível e propor controles antes do projeto começar.
Dado Pessoal vs Dado Pessoal Sensível
Dado Pessoal (Art. 5º, I)
Nome · CPF · RG · E-mail · Telefone
Número de conta · Histórico de transações
Score de crédito · Endereço · IP
Dado Pessoal Sensível (Art. 5º, II) — proteção reforçada
Origem racial ou étnica
Convicção religiosa · Opinião política
Dado de saúde ou vida sexual
Dado genético ou biométrico (reconhecimento facial)
📌 Em banco: CPF, renda, histórico de transações = dado pessoal. Biometria para autenticação = dado pessoal sensível com proteção reforçada.
Bases Legais mais relevantes em banco (Art. 7º)
Base LegalQuando se aplicaExemplo
Execução de contratoNecessário para cumprir contrato com o titularProcessar pagamento do cliente
Obrigação legalLei exige o tratamentoReporte ao BACEN, declaração ao Fisco
Legítimo interesseInteresse razoável do controladorPrevenção a fraudes
Proteção ao créditoEspecífica para análise de riscoConsulta ao Serasa
ConsentimentoTitular autorizou expressamenteOpt-in para marketing
📌 Em banco regulado, a maioria dos tratamentos está coberta por "execução de contrato" ou "obrigação legal". Consentimento é menos comum porque a relação contratual já legitima o uso.
Anonimização — irreversível
Após aplicado, o dado deixa de ser pessoal e sai do escopo da LGPD.
CPF: 123.456.789-00 Após: *** (sem forma de recuperar)
📌 Os dados sintéticos do Painel de Produtividade são anônimos — nenhum responsável é uma pessoa real.
Pseudonimização — reversível com chave
O dado continua sendo pessoal (ainda está na LGPD), mas protegido. Deve ser usado em ambientes de dev e testes.
CPF: 123.456.789-00 Após: hash_a7f3c2b1 (reversível com a chave)
📌 Em banco: dados de clientes em ambiente de desenvolvimento devem ser pseudonimizados, nunca reais.
Privacy by Design — privacidade desde o requisito
Privacidade não é um add-on no final do projeto — é incorporada ao design desde o início. Quando uma demanda chega solicitando cruzar dados de transação com dados comportamentais de app, a análise LGPD é feita antes de escrever o escopo.
Pergunta de Privacy by Design (antes do escopo): 1. Qual é a base legal? 2. O titular foi informado? 3. É necessário usar dado individual ou dado agregado resolve o objetivo? 4. Qual o prazo de retenção máximo? 5. O DPO precisa ser consultado?
📌 Contexto bancário adicional: Resolução BCB 4.893/2021 exige política de segurança da informação e cibernética. Lei Complementar 105/2001 protege o sigilo bancário. Dois ângulos de conformidade: LGPD (ANPD) + regulatório (BACEN).

Insights do Módulo 4

🏛
Data Steward é o papel de PMO de Dados
Não é o título que muda — é o posicionamento. O Data Steward conecta negócio e tecnologia na gestão do dado: documenta, valida qualidade e garante que o KPI publicado reflete a realidade. É exatamente o que um PMO de Dados faz quando estrutura uma demanda, define métricas e revisa um dashboard antes de publicar.
🛡
LGPD em banco é design, não compliance reativo
Em instituição financeira regulada, a pergunta LGPD não é feita no final do projeto — é parte do requisito. Identificar a base legal, avaliar risco de reidentificação e definir se dado agregado resolve o objetivo são itens do escopo, não da auditoria. Quem domina esse vocabulário chega à reunião já com as respostas que o jurídico vai perguntar.
⚠
ResponsavelID é pessoal indireto — nível de raciocínio que diferencia
A coluna ResponsavelID é um número — parece não pessoal. Mas combinada com responsaveis.csv, identifica um colaborador (pessoa física). Esse nível de análise — pensar em como o dado se torna pessoal em combinação com outras fontes — é o que distingue uma análise LGPD superficial de uma análise real. É também o tipo de pergunta que aparece em entrevistas técnicas de PMO de Dados em banco.
🔎
Dado comportamental pode inferir dado sensível
No mapa de riscos, o cenário de cruzamento de transações com navegação no app gerou a observação de que padrões de compras podem inferir origem étnica, convicção religiosa ou condição de saúde. Um dado não sensível pode criar inferência de dado sensível quando cruzado. Privacy by Design existe justamente para identificar isso antes do projeto começar.
📈
Entrada manual via Excel é o maior risco operacional do pipeline
No mapa de fluxo, a entrada via Excel foi classificada como Alta probabilidade / Alto impacto. Dado manual sem rastreabilidade é o tipo de vulnerabilidade que aparece em auditorias bancárias. A mitigação documentada — substituir por integração direta — é exatamente a justificativa de um projeto de dados que um PMO vai levar para aprovação.
📄
4 documentos no mesmo dataset criam consistência de portfólio
SQL, Power BI, Excel e Governança aplicados ao mesmo Painel de Produtividade mostram que você não só conhece as ferramentas — você as integra em torno de um problema de negócio real. Para um recrutador, é a diferença entre ver projetos soltos e ver uma profissional que pensa em soluções.
