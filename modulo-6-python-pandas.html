Aula 1 — Importação e os 3 Diagnósticos

Carregar um CSV parece trivial — até esbarrar nos três perrengues clássicos de dados brasileiros. Passar por eles na ordem é praticamente um rito de iniciação da análise de dados no Brasil.
import pandas as pd demandas = pd.read_csv("demandas.csv", encoding="utf-8") demandas.head() # espia as 5 primeiras linhas
Os três diagnósticos, na ordem em que aparecem
Sintoma / erroCausaCorreção
Conteúdo estranho, JSON, NaNArquivo errado (tema/dinâmica, não os dados)Exportar a aba de dados brutos
UnicodeDecodeError: byte 0xe1Encoding — acento gravado em Latin-1 (Excel PT-BR)encoding="latin-1"
Expected 1 field, saw 7Separador — Excel PT-BR usa ;sep=";"
🧭
Régua de leitura de erro: "byte inválido" = encoding; "expected X fields" = separador. No fim, cada arquivo pode ter sua própria regra — neste dataset, a demandas vinha com ; e as dimensões com ,. Inspecionar antes de confiar é metade do trabalho.
🔗

Aula 2 — Merge: Star Schema em Pandas

A fato sozinha só tem IDs (SquadID = 5). O merge troca cada ID pelo atributo legível da dimensão — é o LEFT JOIN do SQL. Encadeamos 5 merges, um por dimensão.
df = ( demandas .merge(squads, on="SquadID", how="left") .merge(status, on="StatusID", how="left") .merge(prioridade, on="PrioridadeID", how="left") .merge(categoria, on="CategoriaID", how="left") .merge(responsaveis, on="ResponsavelID", how="left") )
how="left"
Mantém todas as 420 demandas e traz os dados da dimensão. Se o total de linhas mudasse, seria sinal de ID duplicado numa dimensão — sempre confira com df.shape.
A colisão _x / _y
Tanto squads quanto responsaveis tinham SquadNome. O Pandas renomeia para _x (o que já estava) e _y (o novo). Não é erro — é redundância do modelo: o squad chega por dois caminhos. Mantém-se o da relação principal.
🧹

Aula 3 — Limpeza: Selecionar e Renomear

Depois dos merges, 20 colunas — mais do que o necessário. Selecionamos só o essencial e damos nomes limpos, resolvendo o _x/_y.

Aula 5 — SLA: Datas e o Denominador Correto

A pergunta de PMO: "quantas demandas fecharam dentro do prazo?". Antes de comparar datas, é preciso convertê-las de texto para tipo data.
# 1) texto → data (senão a comparação não funciona) df["DataPrazo"] = pd.to_datetime(df["DataPrazo"]) df["DataFechamento"] = pd.to_datetime(df["DataFechamento"]) # 2) cumpriu o SLA? fechou até o prazo? df["Cumpriu_SLA"] = df["DataFechamento"] <= df["DataPrazo"] # 3) só as FECHADAS (abertas não têm SLA a avaliar) fechadas = df[df["DataFechamento"].notna()] fechadas["Cumpriu_SLA"].mean() # → 0.7575
Resultado — validado contra o card do dashboard
MétricaValorObservação
Demandas fechadas301A base correta (não 420)
Cumpriram o SLA228Fecharam até o prazo
% SLA75,75%228 ÷ 301 — idêntico ao Painel
🎯
O denominador certo: o SLA usa as 301 fechadas, não as 420 totais — demanda em aberto não tem cumprimento de prazo a avaliar. Saber qual é o denominador correto é o que separa quem faz conta de quem entende o negócio. Pensamento de PMO, não de operador de ferramenta.

Erros Comuns (todos vividos nesta sessão)

⚠️1. Subir o arquivo errado
Um tema.json do Power BI e uma tabela dinâmica exportada foram carregados por engano. O Pandas lê qualquer coisa — cabe a você verificar se é o dado bruto (uma linha por demanda), não um resumo.
⚠️2. Encoding — byte 0xe1
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xe1
✅ Correção
encoding="latin-1" (ou cp1252). Padrão do Excel PT-BR.
⚠️3. Separador — Expected 1 field
ParserError: Expected 1 fields in line 5, saw 7
✅ Correção
sep=";". O "7" no erro é uma pista: são as 7 colunas grudadas.
⚠️4. Variável quebrada na memória — KeyError
KeyError: 'SquadID'
Uma dimensão foi carregada com separador errado numa célula anterior e ficou "quebrada" na memória. Num notebook, a variável guarda o último valor recebido, não a ordem visual das células.
✅ Correção
Recarregar os dados do zero numa célula limpa. Reflexo certo quando algo "deveria funcionar e não funciona".
⚠️5. Biblioteca não instalada — ModuleNotFoundError
ModuleNotFoundError: No module named 'matplotlib'
✅ Correção
pip install matplotlib no terminal → Restart do kernel → Run All. No local, o ambiente é você que monta (diferente do Colab).

Insights da Aula

O denominador certo é decisão de negócio
Filtrar as 301 fechadas em vez de dividir por 420 não é detalhe técnico — é entender o que o indicador significa. Esse tipo de julgamento é o núcleo do papel de PMO de Dados.
🧭
Diagnosticar erro é literacia de dados
Arquivo errado → encoding → separador → memória → biblioteca: cinco erros, cinco diagnósticos. Esse é o fluxo real de quem trabalha com dados. Saber ler a mensagem de erro e agir vale mais que decorar sintaxe — e não está em curso nenhum.
