0. Fundamentos de Dados & BI 🔴 COMECE AQUI

▼
Semana 1 🔴 Base obrigatória ⏱️ ~12 horas
Por que começar aqui? Antes de escrever SQL ou criar dashboards, você precisa entender o vocabulário e o fluxo dos dados. Esta base vai destravar todos os outros módulos — sem ela, você decora; com ela, você entende.

📚 Conteúdo para estudar

  • Curso: Modelagem Dimensional (buscar na Alura) Alura
    Fato, dimensão, esquema estrela — vocabulário básico

🎯 Conceitos-chave que você precisa dominar

  • Diferença entre dado, informação e conhecimento Conceito
    Você vai usar essa distinção em apresentações executivas
  • Tipos de dados: estruturados, semi-estruturados, não estruturados Conceito
    Tabela (SQL), JSON (API), e-mail/PDF/imagem
  • ETL vs ELT — extração, transformação e carga Conceito
    Saber quando se usa cada um e por quê
  • Data Warehouse vs Data Lake vs Lakehouse Conceito
    Onde o Santander tipicamente armazena o quê
  • Modelagem dimensional: fato, dimensão, estrela vs floco de neve Conceito

  • KPI, métrica, dimensão, granularidade Conceito
    A diferença entre os 4 é o que separa um bom PMO de um excelente
  • Pipeline de dados: origem → transformação → análise → visualização → decisão Conceito
    Saber em que etapa um problema mora ajuda a alocar o time certo

🛡️ LGPD & Compliance Bancário (essencial no Santander)

Por que isso importa para você? Em banco regulado, LGPD não é um item de compliance — é parte do design de qualquer iniciativa de dados. Você vai precisar saber identificar dado pessoal, dado sensível e propor controles antes do projeto começar.
  • Lei Geral de Proteção de Dados (texto oficial — ANPD) Leitura
    Foque nos artigos 5º (definições), 7º e 11 (bases legais), 46-49 (segurança)
  • Curso: LGPD na prática (buscar na Alura) Alura
    Visão aplicada a TI e dados
  • Conceito: dado pessoal vs dado pessoal sensível Conceito
    Sensível: origem racial, religião, biometria, saúde, orientação sexual
  • Conceito: anonimização vs pseudonimização Conceito
    Anonimização: irreversível (sai da LGPD). Pseudonimização: reversível com chave (continua na LGPD)
  • Conceito: Privacy by Design e papel do DPO Conceito
    Privacidade pensada desde o requisito, não como remendo no final
  • Exercício LGPD 1: Classificar dados de uma base que você usa Prático
    Para cada coluna: é pessoal? é sensível? qual a base legal de uso?
  • Exercício LGPD 2: Mapear riscos LGPD de um projeto fictício Prático
    "Quero cruzar dados de cartão com behaviour de app" → quais cuidados?

🛠️ Ferramentas de PMO (onde o trabalho realmente acontece)

Antes de estudar processos, conheça as ferramentas. Saber operar bem ao menos uma ferramenta de cada categoria já te diferencia: gestão de demanda + documentação + cronograma.
  • JIRA ou Azure DevOps — gestão de demandas e tickets Ferramenta
    Onde as demandas viram tarefas. Aprenda boards, filtros, JQL básico ou queries do Azure DevOps
  • Atlassian Agile Coach (gratuito) Curso
    Conceitos práticos de JIRA + Scrum/Kanban
  • Confluence ou SharePoint — documentação viva de projetos Ferramenta
    Organize TAPs, runbooks, atas, decisões. Páginas linkadas valem mais que pastas
  • MS Project ou Planner ou Monday — cronograma e roadmap Ferramenta
    Para projetos pequenos, Planner basta. Para projetos com dependências, MS Project
  • Miro ou Lucidchart — diagramas, fluxos, jornadas Ferramenta
    Essencial para apresentar arquitetura de dados, fluxo de processos, dependências
  • Exercício: Montar um board JIRA/Azure DevOps fictício com 10 demandas Prático
    Crie épicos, histórias e tarefas. Use a versão gratuita do JIRA Cloud
  • Exercício: Criar uma página Confluence/SharePoint de projeto Prático
    Inclua: objetivo, escopo, time, status, decisões, links para artefatos

💰 Orçamento e custos de projetos de dados

  • Licenças de BI: Power BI Pro (~US$ 10/usuário/mês) vs Premium (capacidade) Conceito
    Quando vale migrar — em geral acima de 500 usuários ou para datasets > 1 GB
  • Custos de cloud: Azure / AWS / GCP — modelo de cobrança por consumo Conceito
    Saber estimar storage + compute + queries para defender orçamento
  • Exercício: Estimar TCO (Total Cost of Ownership) de um projeto fictício Prático
    Licenças + cloud + horas-pessoa por 12 meses

📊 Métricas de saúde de área de dados

  • Cycle time e lead time de uma demanda Conceito
    Da abertura ao fechamento — mede agilidade real do time
  • Throughput: demandas entregues por sprint/mês Conceito
    Mais útil que velocity para times de dados (que mistura tipos de demanda)
  • Qualidade: % de retrabalho, incidentes de dados, SLA de relatórios Conceito
    Boas métricas de qualidade reduzem fogo amigo do negócio
  • Exercício: Definir 5 métricas de saúde para sua área Prático
    Como você reportaria a saúde da operação para um diretor?

▼

Por que isso é diferencial? Análise técnica sem comunicação morre na gaveta. Saber traduzir números em decisão é o que separa um PMO operacional de um PMO estratégico.

📚 Conteúdo para estudar

    Referência mundial — leia 1 post por semana
  • Artigo HBR: How to Give a Killer Presentation Leitura
    Princípios de apresentação executiva

🎨 Storytelling com dados (visual)

  • Pirâmide invertida: insight primeiro, detalhes depois Conceito
    Diretor não tem tempo para "deixa eu explicar como cheguei aqui"
  • BANs (Big Ass Numbers) — KPIs em destaque Conceito
    O número que importa precisa ser o primeiro que olho vê
  • Cor com propósito: cinza para contexto, cor só para destaque Conceito
    Arco-íris = ruído. Acessibilidade importa (8% dos homens têm daltonismo)
  • Exercício: Critique um dashboard público e sugira melhorias Prático
    Documente em 1 página — antes/depois
  • Exercício: Reformatar um dashboard interno aplicando os princípios Prático
    Pegue um dashboard do seu trabalho e proponha versão 2.0

🎙️ Comunicação Executiva (apresentar para C-level)

Regra de ouro: diretor não quer entender a análise — quer saber o que decidir. Comece pela decisão, justifique com 3 pontos, e tenha o detalhe pronto se perguntarem.
  • Estrutura SCQA: Situação → Complicação → Pergunta → Resposta Conceito
    Estrutura clássica McKinsey para apresentações estratégicas
  • Princípio da pirâmide (Minto): resposta primeiro, depois suporte Conceito
    Top-down. Apresente a conclusão e desça nos detalhes só se perguntarem
  • Status report semanal: status / progresso / bloqueios / próximos passos Conceito
    RAG (Red/Amber/Green) com 1 linha explicando o porquê de cada cor
  • Steering committee: rituais, papéis, governança Conceito
    Como conduzir um comitê de patrocinadores que decide rumo de projeto
  • Exercício: Escrever um status report de 1 página de um projeto fictício Prático
    Use RAG + 3 bullets para cada status. Máximo 1 página
  • Exercício: Slide executivo de 1 página com decisão + justificativa Prático
    Use a estrutura: "Recomendo X porque (1) (2) (3). Risco: Y. Mitigação: Z."
  • Exercício: Apresentar 5 minutos para um espelho ou gravar vídeo Prático
    Pegue um dashboard e apresente como se fosse para um diretor. Cronometre
